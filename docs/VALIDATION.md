## 驗收範圍

HTTP檢查包含錯誤帳密、session ID更新、Cookie屬性、登出後舊cookie失效、全部寫入CSRF、帳號與member／owner權限、CRUD、有效日期／預算／欄位驗證、SQL字元作一般資料、GET不修改狀態、版本409與冪等重試。

第二階段24個HTTP情境覆蓋每日項目CRUD、跨日移動、連續排序及完整ID集合驗證，費用CRUD及分類／預算摘要，成員付款及分攤名單，三人100元的34／33／33餘數分配與精確結算，明細／費用／基本資料共享版本，兩個client同版本僅一次提交、相同key只有一筆支出，跨行程child ID隔離，日期縮短不排除既有資料及刪除cascade。

瀏覽器驗收包含登入、清除localStorage後行程仍存在、不同cookie context資料隔離、CRUD／預算／狀態、延遲載入、500保留表單、已提交但回應遺失時重試不重複、兩分頁版本衝突、401清除快照、初始化失敗恢復，以及使用者輸入以文字呈現。

第二階段18個瀏覽器情境實際從列表連到PHP明細與費用頁，驗證新增／編輯／刪除、每日順序、跨日移動、費用及預算刷新保存、成員只讀、500保留輸入、明細／排序／預算409的明確核對、真正登出與分頁換帳號，以及手機390px畫面與表單。新增三個案例驗證預算、每日項目及費用發生409後再遇GET500，仍能保留草稿、只重試讀取、核對新版本後繼續儲存，不需要重新整理或自動重送寫入。

回應遺失後的POST重試另有其他分頁先新增資料，驗證冪等receipt仍只有一筆原新增且前端取得最新快照，不隱藏後來修改。POST已確認成功但後續GET失敗時，顯示「已儲存」並暫停過期明細操作；重新載入只重試GET，不再POST。

獨立覆核另外重現「另一個分頁切換帳號後，舊分頁重試把新帳號行程顯示在舊姓名下」。已由後端回傳實際帳號標頭、前端在使用回應前核對並清除舊畫面修正。第11項瀏覽器回歸案例及獨立DOM觀察都確認不再出現錯誤帳號下的行程。

第二階段獨立覆核以300組不同成員、付款人、分攤名單與金額的帳本，和獨立Python整數計算比對，再套用結算至各人餘額0；亦包含付款人未參與分攤與數字形字串ID。另以真正第一階段提交初始化的資料庫驗證升級，確認自訂資料與session內容保留、已刪除的示範帳號不會重新建立。

## 重跑

完整指令、相依套件與Apache隔離測試方法見 [tests/README.md](../tests/README.md)。

```bash
python3 tests/run_acceptance.py
```

runner自動建立臨時資料、啟動PHP、執行HTTP驗收、停止重啟確認資料、執行瀏覽器驗收，最後關閉伺服器與清理臨時資料。任一失敗會回非零退出碼。

僅檢查後端時：

```bash
python3 tests/run_acceptance.py --http-only
```

此模式明確略過瀏覽器，不宣稱完整驗收通過。GitHub Actions使用同一完整runner；遠端執行結果以該提交的Actions紀錄為準。
